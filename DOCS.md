## 3. Архитектура

Статический сайт на GitHub Pages + Google Apps Script как «облако» + Google Sheets как хранилище.
Сервера нет: вся логика в браузере, общие данные — в таблице через Apps Script.

### Файлы сайта (корень репозитория)
- `index.html` — калькулятор для менеджеров.
- `admin.html` — админка (вход по менеджер+пароль).
- `config.js` — v6: ставки, коэффициенты, менеджеры, 9 марок, справочники семейств (refs),
  каталог работ с бирками (req), категории, CAT_ICONS, AWD_NAMES, buildPassport, collectWorks, validateWorks.
- `core.js` — v3: общее ядро ($, el, formatRub, debounce, cleanDate, fmtShort, cloudSend, cloudGet,
  brandDBByName, ensureBrand, BRAND_PREFIX, ICON_FALLBACK, AWD_FALLBACK, brandIdPrefix, catIcon, awdName).
- `app.js` — v10: логика калькулятора (плитки марок, цепочка селектов, поиск, работы, расчёт, журнал, история).
- `admin.js` — v11: логика админки (логин/пароли/сессия 24ч, журнал изменений, ставки, коэффициенты,
  менеджеры, очередь заявок со статусами, форма модификации с предпросмотром паспорта).
- `style.css` — финальная сборка: строгий монохром, логотип в цвете, плитки, крестики v2, мобильные брейкпоинты.
- `brands/*.js` — базы марок (9 файлов): volkswagen, audi, skoda, seat, porsche, bmw, mini, alpina, mercedes.
- `img/logo.png` — логотип сервиса; `img/brands/*` — логотипы марок (svg или png).

### Облако (Apps Script v6 + Google Sheets)
Листы таблицы: «Заявки», «Журнал расчётов», «Журнал изменений», «Пароли».
Действия doPost: addRequest, addCalc, addLog, setPass, setStatus, deleteRequest, deleteCalc.
Действия doGet: getPass, getRequests, getCalcs, getLogs.
Ссылка /exec хранится в config.js (cloudUrl). При изменении скрипта ОБЯЗАТЕЛЬНО
«Управление развертываниями → Новая версия → Развернуть», иначе правки не применятся.

### Загрузка баз марок
Файлы марок лежат в `brands/` и подгружаются лениво (ensureBrand из core.js) в момент выбора марки.
В index.html/admin.html предзагружается только `brands/volkswagen.js`.
Важно: базы объявлены через `const`, их НЕТ в window — доступ только через brandDBByName (eval).

## 4. Схема данных

### Модификация (паспорт)
Поля: id, model, generation, engine{code,volume,power,torque}, gearbox{code,type,gears},
drive, awdSys, suspension(spring|air), rear(multilink|beam), parking(epb|mech),
battery(hood|trunk|seat), pf(true|false|отсутствует), fluids{...}, customNh{...}.
Массива works НЕТ: список работ выводится функцией collectWorks по биркам паспорта.

### Бирки собираются из справочников config.refs
- engineCodes → engineFamilies: fuel, timing(belt|chain), injection, turbo.
- gearboxFamilies: gbType(dsg|manual|automatic).
- Остальное — явные поля модификации (drive, awdSys, suspension, rear, parking, battery, pf).
- Работы каталога имеют req (требования к биркам); работа попадает в модификацию,
  только если все req совпали. Ошибки вида «цепь на ременном моторе» невозможны по построению.

### Нормо-часы
- База — в каталоге работ (усреднённые, красная точка в интерфейсе).
- customNh модификации — проверенные значения (зелёная точка).
- Правило владельца: отклонение кастома от базы до ±0.5 допустимо; больше — только с подтверждением практикой.

### Префиксы id модификаций
Исторические: vw_ (Volkswagen), mb_ (Mercedes). Учёт в core.js (BRAND_PREFIX) и в app.js (modBrandId).

## 5. Правила работы и безопасности

- Релиз-точки (Release/Tag) после каждого рабочего комплекса. Текущая последняя: v1.7 (общее ядро core.js).
- Вход в админку: пара «менеджер + пароль»; сессия 24 часа; пароли хранятся в листе «Пароли»
  как SHA-256 отпечатки (не в коде). Первый вход менеджера = установка пароля.
- Журнал изменений: все действия админки пишутся в лист «Журнал изменений» с менеджером и временем.
- Репозиторий публичный → cloudUrl виден посторонним (риск спама в таблицу принят осознанно).
  При желании лечится ротацией ссылки Apps Script или приватным репо (тогда слетит бесплатный Pages).
- Запчасти и VIN-подбор в калькуляторе НЕ реализуются (решение владельца): подбор запчастей только
  человеком по VIN в дилерских каталогах.

## 6. Грабли и уроки (чтобы не повторять)

- `const` в отдельном script-файле не попадает в window: искать базы только через brandDBByName.
- Google Sheets превращает строки дат в Date-ячейки; при чтении возвращать строки через Utilities.formatDate,
  иначе в интерфейс прилетает «GMT+0600 (Омск…)». Дублирующая страховка cleanDate на клиенте.
- Дубли функций между app.js и admin.js приводили к рассинхрону правок → вынесены в core.js.
- Эмодзи на инвертированных (primary) кнопках в тёмной теме выглядят серыми кляксами → убраны.
- Стандартный <select> не показывает картинки → выбор марки сделан плитками с логотипами.
- Старые авто-срезы репозитория в контексте диалога бывают битыми: доверять только чтению репозитория напрямую.
